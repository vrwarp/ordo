# M4: the editor for churches (work items)

[design/27](../../../../../docs/design/27-pptx-native-renderer.md) §15 M4, built on §11 "Editor extensions
for churches" and "Round trip and migration", §3 (TextRun, TextPara, TextStyle box fields, ObjectOrigin,
`locked`, Slide.pptx), §6 (the text engine the editor draws with) and §14 items 9 and 12. The priority:
slides imported from PowerPoint are **editable** by a volunteer, and ordo's editor grows where a church needs
it (fix a lyric typo, change a date, add a verse, swap the series background), never into a PowerPoint
clone (§11 "Not built").

The scaffold (`m4/scaffold`) puts every contract in place so eight items are built in parallel, each in its
own files. Everything it adds is a stub that changes nothing (the editor behaves as M3 left it), except
what is listed under "Built in the scaffold".

**Status: every item is built and merged (`m4/integrate`, "Integration" below).** The stubs this file
describes are what the items started from; none is left in the code.

Every op is pure and returns its input itself (the same object) when it changes nothing, so `change()`
records no undo step and the draft stays saved. The editor applies an M4 op only through `actions.ts`:
each action is one undo step (200 deep, coalesced per key within 800 ms where the action gives a key),
marks the draft unsaved, and saves with the presentation through `save()` (PUT with the base rev; 409,
423 and the size budgets handled there, revisions written by the hub). The object actions leave `locked`
objects alone; group actions move, resize, delete and reorder them (design/27 §11 "Locked objects").
`apps/operator/test/m4-scaffold.test.ts` checks every stub and the wiring: replace your stub expectations
there with real tests as you build.

### The store

`editorStore.ts` keeps the selection as `objectIds` (every selected object, in the slide's z order) beside
`objectId` (the primary one, which the Object panel edits): `selectObject(id)` selects one,
`selectObjects(ids, primary?)` several (ids not on the open slide are left out), `currentObjects()` reads
them, and undo, redo and adopting a job's save keep the selection to what still exists. Nothing else in the
store changed. `inspect.ts` exposes a read-only view of the editor on `window.__ordo.editor()` (imported by
`EditorView.tsx`) for the end-to-end specs.

- **Untrusted decks.** Build decks synthetically (`churchDeck`, `e2e/pptxdecks.ts`,

- **Docs move with the code** (design/24): design/15 "Editor" for what you build, design/16 for the stage
  (G), design/11 for fields (D), design/12 for the re-import job (F), and an "As built" line per item under
